---
'genie-react': minor
---

Waits no longer report an app settled when Genie could not see all of it, and the hub stays discoverable across a Vite restart.

- `react_pending_work` stops each call after 50,000 fibers, and `react_quiesce`, `devtools_wait` and `verify` used to ignore its `scanTruncated` flag. On a larger tree they could report React idle while a Suspense fallback past that point was still on screen, and `verify` could return `pass` on that settle. Each call now resumes the walk where the previous one stopped, as long as no commit has landed, and reports `scannedFibers`. The hub never counts a partial scan as idle. Its reason says how many fibers the scan has covered, so a large tree settles once the scan has covered it, and `verify` refuses with `not_quiescent` until then.
- TanStack Router releases built on router-core 1.171.3x, which the current `@tanstack/react-router` 1.170.4x installs, dropped `statusCode`, `loadedAt` and the `pendingMatches` store. `router_get_state` then always reported `pendingMatchCount: 0` and never listed `pending-matches`, even while a navigation's matches were loading. It now counts the matches of the in-flight load on those releases. `statusCode` and `loadedAt` are omitted where the router no longer provides them, and a not-found navigation is detected from its matches.
- After a reload, the new document says hello before `<Genie>` registers the Query and Router collectors again. `devtools_wait` with `condition: "settled"` used to fail at once with "Domain query requires unavailable tool query_is_fetching". `verify` dropped the Query domain from its default settle domains. A domain that an earlier document of the same tab advertised is now waited on until it registers again. If it never does, the domain stays `pending` with a reason saying it was not observed in this document.
- When Vite restarts its server inside the same process, it builds the new server before it closes the old one. The old server's close handler then deleted the new server's `.genie/bridge.json` and token file, because ownership was checked by process ID only. It also closed the new server's bridge, so the CLI lost the hub until the next restart. Each publication now records its own instance ID, and removal deletes only the files that carry it, under the same lock publication uses. Each Vite server closes only the bridge it created. `removeDiscoveryFile`, `removeDiscoveryFileSync` and `removeDiscoveryOnExit` accept that instance ID, and `writeDiscoveryFile` returns it.
- `react_get_renders` with default arguments failed once more than 5,000 components matched, which a 500-row table reaches. It now returns one bounded page instead, as with `includeCursor: false`: the summary covers every match, `omittedByLimit` counts the rows past `limit`, and `pagination.cursorOmitted: "candidate-limit"` says why there is no cursor.
