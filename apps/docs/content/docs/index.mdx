Genie gives a coding agent access to the React app that is running now. It can inspect component
state, explain renders, read Query and Router state, and record an interaction across those domains.

Pair Genie with a browser or device driver. The driver clicks, types, and checks the screen. Genie
reads what happened inside the app. A useful check needs both the expected UI and runtime evidence.

Once the intended session is ready, give your agent a concrete task:

> Use Genie to find why Checkout renders when I type in search. Fix it, then repeat the interaction and verify checkout still works.

The [agent workflow](/docs/getting-started/agent-workflow) explains how to discover tools, target the
right session, and collect evidence. [CLI output](/docs/getting-started/cli-output) covers JSON,
scripting, and differences between current source and published packages.

## Choose a task

| What you need to know | Follow this guide |
| --- | --- |
| Why did this component render? | [Render optimization](/docs/workflows/render-optimization) |
| Is the delay in a request or React rendering? | [Interaction timeline](/docs/workflows/interaction-timeline) |
| Did fresh Query data reach the UI? | [Query updates](/docs/workflows/query) |
| Do loading and error screens work? | [Loading and errors](/docs/workflows/loading-and-errors) |
| Did the fix help across repeated runs? | [Performance comparison](/docs/workflows/performance-proof) |
| Can the agent use our fixtures or login helpers? | [App tools](/docs/tools/app-tools) |

Genie labels incomplete coverage and uncertain causes. Read those labels before treating an empty
result as a clean bill of health or a smaller timing as proof of an improvement.

Use the [tool reference](/docs/tools) for individual calls and the [case studies](/docs/case-studies)
for recorded examples with their limits.
