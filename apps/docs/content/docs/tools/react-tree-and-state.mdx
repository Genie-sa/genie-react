## `react_get_tree`

Returns a bounded flat view of the mounted React tree.

**Input:** `rootId` is an optional integer. `depth` is an integer from 1 to 80 and defaults to 30.
`includeHost` defaults to `false`. `maxNodes` is an integer from 1 to 2000 and defaults to 400.
`appOnly` defaults to `true`: fold away components known to be library code (framework routers, providers, icon and link components) and reconnect parent links through them, so the tree starts where your own components start. `depth` then counts only the levels shown. Components whose ownership is unresolved stay, marked `ownership: "unknown"`, and `filteredNote` counts what was hidden and what is unknown. Ownership comes from each component's own code: the frames of its body that React records when it creates elements, or the React 18 `_debugSource` of the elements it renders, never from the parent JSX that created it. Ownership is resolved on at most 5000 candidates before `maxNodes` caps the output. `ownershipCoverage` describes that candidate set, and `truncated` discloses omitted tree structure. Use `appOnly:false` for the raw tree.

```bash
npx @genie-react/cli call react_get_tree \
  '{"rootId":7,"depth":5,"maxNodes":100,"appOnly":true}' --json
```

**Output (selected fields):**

```json
{
  "rootId": 7,
  "nodes": [
    {
      "id": 7,
      "parentId": null,
      "name": "Checkout",
      "key": null,
      "kind": "component",
      "source": {
        "file": "/src/Checkout.tsx",
        "line": 18,
        "column": 1,
        "functionName": "Checkout"
      },
      "isLibrary": false
    }
  ],
  "total": 18,
  "truncated": false,
  "truncatedBy": null,
  "omitted": { "depth": 0, "maxNodes": 0 }
}
```

`omitted` counts the nodes each limit left out; both can be non-zero, so raising one limit can still
leave nodes out. A node that `depth` cut off carries `omittedDescendants`; pass its `id` as `rootId`
to read them.

Without `rootId`, the tree starts at the app's root. A root mounted inside another root's DOM, such
as a widget that bundles its own React (Clerk) or a separate `createRoot` island, is never chosen as
the app root. Those roots are listed in `otherRoots` as `{ "rootId", "name" }`, one per root's top
component; the field is absent when the page has one root.

A node's `kind` is `component`, `host`, or `suspense` for a Suspense boundary. Error boundaries are
`component` nodes with `errorBoundary: true`. The `boundaryId` that `react_error_state` and the `id`
that `react_suspense` report are these node ids, so a boundary can be passed to
`react_inspect_component`, found with `react_find_components` (`"component":"Suspense"`), and read as
`rootId`.

**Agent use:** Use `rootId` to inspect the returned instance, or raise `depth` or `maxNodes` when
`omitted` shows that the tree is incomplete. Pass an `otherRoots` entry's `rootId` to read that
root's tree.

## `react_provenance`

Reports wrapper ancestry, source roles, ownership, and source-map health for mounted components.

**Input:** `component` is an optional exact display name; `exact` defaults to `true`, and `false` matches every name containing it, ignoring case. `componentMatch` reports which names matched. `limit` is an integer from 1 to 500
and defaults to 200. `appOnly` defaults to `false`; `true` hides records known to be library code
and keeps unresolved ones as `unknown`.

```bash
npx @genie-react/cli call react_provenance \
  '{"component":"SearchRow","limit":50,"appOnly":false}' --json
```

**Output (selected fields):**

```json
{
  "records": [
    {
      "id": 44,
      "name": "SearchRow",
      "wrapperAncestry": [
        { "kind": "memo", "name": "Memo" },
        { "kind": "forward-ref", "name": "SearchRow" }
      ],
      "ownership": "unknown",
      "source": null,
      "provenance": {
        "definitionSource": null,
        "allocationCallsite": null,
        "hookDefinitionOwner": null,
        "hookCallsite": null,
        "package": null,
        "sourceMapConfidence": "unknown",
        "failureReason": "definition-and-allocation-not-distinguished",
        "usageOrDefinitionFallback": {
          "file": "/src/SearchRow.tsx",
          "line": 18,
          "column": 2,
          "functionName": "SearchRow"
        }
      }
    }
  ],
  "summary": {
    "scanned": 1,
    "returned": 1,
    "resolved": 0,

```

**Agent use:** Edit a file only when the relevant source role and ownership are resolved. Here the
fallback is ambiguous, so first fix or inspect source maps instead of treating it as the definition.

## `react_find_components`

Finds mounted components by display name.

**Input:** `component` is the canonical non-empty display-name selector. Legacy `query` remains an alias; provide at least one and make them agree if both are supplied. `exact` defaults to `false`. `limit` is an integer from 1 to 200 and defaults to 50. `appOnly` defaults to `false`; `true` excludes library and unknown ownership before the output limit. The search covers every live React root, the app root first, including widgets that bundle their own React. `ownershipCoverage`, `scanTruncated`, and `omittedByLimit` disclose the bounded candidate scan (up to 5000 matching components). `cursor` continues a search with the `nextCursor` it returned; pass only `cursor` and optional `limit`. The match order is fixed when the search starts, so pages never repeat or skip a match, and a match that unmounted between pages is counted in `unmountedSinceSearch` instead of returned.

```bash
npx @genie-react/cli call react_find_components \
  '{"component":"CheckoutForm","exact":true,"limit":20}' --json
```

**Output (selected fields):**

```json
{
  "matches": [
    {
      "id": 42,
      "name": "CheckoutForm",
      "path": "App > Checkout > CheckoutForm",
      "kind": "function",
      "props": { "step": 2 },
      "source": {
        "file": "/src/CheckoutForm.tsx",
        "line": 18,
        "column": 5,
        "functionName": "Checkout",
        "role": "element-callsite"
      },
      "isLibrary": false
    }
  ],
  "omittedByLimit": 0,
  "nextCursor": null,
  "unmountedSinceSearch": 0
}
```

`source.role` says what the location is: `element-callsite` is where the element was created, inside
the parent that `functionName` names; `component-body` is a line inside the component. `line` is
`null` when the file on disk did not show the element at the mapped line, which happens when a
plugin transforms the file without passing a source map on.

**Agent use:** Choose the mounted instance whose ancestor `path`, props, and source match the bug,
then pass its `id` to inspection or mutation tools.

## `react_inspect_component`

Reads bounded props, class state, and hooks for one mounted instance.

**Input:** `id` is a required integer. `path` is an optional array of string or number segments into
props. `depth` is an integer from 1 to 6 and defaults to 2.

```bash
npx @genie-react/cli call react_inspect_component \
  '{"id":42,"path":["user"],"depth":4}' --json
```

**Output (selected fields):**

```json
{
  "id": 42,
  "name": "CheckoutForm",
  "kind": "function",
  "props": { "name": "Ada" },
  "hooks": [
    {
      "index": 4,
      "kind": "state",
      "hook": "useState",
      "stateful": true,
      "stateIndex": 0,
      "customHooks": ["useCheckout", "useStepper"],
      "value": { "step": 2 }
    }
  ],
  "customHookGrouping": "exact",
  "wrapperAncestry": []
}
```

Each hook's `hook` names the React hook that allocated the slot; a hook with several slots, such as
`useTransition` or `useSyncExternalStore`, names each of them. Only `kind` `state` and `reducer` can be
overridden. Each hook's `customHooks` lists the custom hooks that called it, outermost first. It is absent when
the component called the hook directly. To build it, Genie re-renders the component once with React's
hook inspector, the same re-render React DevTools runs when you select a component.
`customHookGrouping` says how far to trust it:

| Value         | Meaning                                                                                                   |
| ------------- | --------------------------------------------------------------------------------------------------------- |
| `exact`       | Every hook carries its custom-hook chain.                                                                 |
| `partial`     | Hooks with `customHooks: null` were hidden from the inspector (`useEffectEvent`); the rest are exact.     |
| `unavailable` | The re-render threw or called different hooks than the mounted render, so no hook carries `customHooks`. |

Values past `depth` or the size limits are placeholders with `__genie_dehydrated__: true`, a `kind`,
a `preview`, and the `path` to re-request. Maps, Sets, Errors, and typed arrays are objects tagged with
`__type`. An object in the app's own data that has a `__genie_dehydrated__`, `__type`, or `…` key is
shown as `{"__type":"Object","entries":[[key, value], …]}`, so those keys always mean Genie's encoding.
`stateIndex` numbers the same hooks in `react_render_causes`, `react_get_renders`, and
`react_override_hook_state`.

**Agent use:** Use the returned `stateIndex` and current value to decide whether a hook override is
needed and which nested `path` to change. Use `customHooks` to find the hook to edit: the last entry is
the innermost custom hook. Hook output stops at 100 entries, and memo-versus-callback detection is best
effort.

## `react_dom_for_component`

Finds host elements rendered by one React component.

**Input:** `id` is a required integer. `limit` is an integer from 1 to 50 and defaults to 10.

```bash
npx @genie-react/cli call react_dom_for_component \
  '{"id":42,"limit":5}' --json
```

**Output (selected fields):**

```json
{
  "id": 42,
  "name": "CheckoutForm",
  "elements": [
    {
      "tag": "form",
      "selector": "[data-testid=\"checkout\"]",
      "domId": null,
      "testId": "checkout",
      "role": "form",
      "ariaLabel": "Checkout",
      "name": null,
      "classes": ["checkout"],
      "text": "Pay now"
    }
  ],
  "total": 1
}
```

A text node the component renders outside any element of its own is listed with `tag: "#text"` and
the selector of the element that contains it.

**Agent use:** Use the returned role, label, test ID, or selector for the next browser action. Prefer
semantic fields when generated CSS classes make the selector brittle.

## `react_component_for_dom`

Finds the React components that own DOM elements: those a CSS selector matches, or the element an
agent-browser snapshot ref names.

**Input:** pass exactly one of `selector`, `ref`, or `box`. `ref` is an agent-browser snapshot ref
such as `@e12`. The CLI reads that element's box and innerHTML with `agent-browser get box` and
`get html` in the session that shows the targeted tab, and sends them as `box`. Other callers pass
`box` (`x`, `y`, `width`, `height` in viewport CSS pixels, plus an optional `html`) themselves. A box
matches the elements whose `getBoundingClientRect()` equals it, innermost first; `html` keeps only
the one with that innerHTML when a wrapper or an overlay shares the box. Read the box again after the
page scrolls or reflows. `limit` is an integer from 1 to 20 and defaults to 5.
`propsDepth` is an integer from 0 to 4 and defaults to 1.
`appOnly` defaults to `false`. With `true`, classify up to 5000 DOM matches before limiting unique
app-owned components. Read `ownershipCoverage`, `omittedByLimit`, and `scanTruncated` before treating
the returned owners as complete.

```bash
npx @genie-react/cli call react_component_for_dom \
  '{"selector":"[data-testid=\"checkout\"]","limit":5,"propsDepth":2}' --json
```

**Output (selected fields):**

```json
{
  "selector": "[data-testid=\"checkout\"]",
  "matched": 1,
  "components": [
    {
      "id": 42,
      "name": "CheckoutForm",
      "kind": "function",
      "tag": "form",
      "props": { "step": 2 },
      "source": {
        "file": "/src/CheckoutForm.tsx",
        "line": 18,
        "column": 1,
        "functionName": "CheckoutForm"
      },
      "isLibrary": false
    }
  ]
}
```

From an agent-browser snapshot:

```bash
agent-browser --session checkout-agent snapshot -i
npx @genie-react/cli call react_component_for_dom '{"ref":"@e12"}' --session checkout-agent
```

**Agent use:** Use the owner `id` and exact source to inspect the visible bug or choose the file to
edit; compare all returned owners when the selector matches more than one element. A ref that the
session's latest snapshot no longer has fails with `invalid_input` and the snapshot command to run.

## `stylex_inspect`

For apps styled with [StyleX](https://stylexjs.com). Explains how elements are styled from the
running page: the applied `stylex.create()` objects (name and source file:line, in override order),
the CSS declarations they resolve to, `defineVars` tokens they read, and runtime values from dynamic
style functions.

**Input:** Supply `selector`, a CSS selector, or `id`, a current component ID. At least one is
required at runtime. The component form describes styled host elements in its rendered subtree,
including nested elements. `limit` is an integer from 1 to 20 and defaults to 5.

```bash
npx @genie-react/cli call stylex_inspect \
  '{"selector":"#pricing article"}'
```

**Output (selected fields):**

```json
{
  "target": "#pricing article",
  "matched": 1,
  "status": { "system": "stylex", "styleSrc": true, "hint": null },
  "elements": [
    {
      "tag": "article",
      "selector": "article",
      "owner": { "id": 82, "name": "PricingCard" },
      "styleObjects": [
        { "name": "styles.card", "package": "@acme/app", "file": "src/PricingCard.tsx", "line": 5 },
        { "name": "emphasis.featured", "package": "@acme/app", "file": "src/PricingCard.tsx", "line": 29 }
      ],
      "declarations": [
        { "property": "border-color", "value": "rgb(228, 81, 30)", "condition": null, "className": "borderColor-x1xsh3er", "tokens": [] },
        { "property": "gap", "value": "12px", "condition": "@media (width >= 48rem)", "className": "gap-x1e7g6uk", "tokens": [] },
        { "property": "width", "value": "var(--x-width)", "condition": null, "className": "width-x5lhr3w", "tokens": [{ "variable": "--x-width", "value": "80%" }] }
      ],
      "dynamic": [{ "variable": "--x-width", "value": "80%" }],
      "inline": [],
      "unresolvedClasses": []
    }
  ]
}
```

`inline` lists ordinary properties from the element's `style` attribute; they beat class rules, and
each declaration they override has `overriddenByInline: true`. `status.hint` names the StyleX plugin option that unlocks more when `system` is `none` or
`styleSrc` is false. `line` is the style key's line (`card: {`).

**Requires** StyleX dev output: set `dev: true` and `debug: true` on the StyleX bundler plugin
(`@stylexjs/unplugin` or the Babel plugin). `dev` alone yields style-object names; `debug` adds
file:line.

**Agent use:** Read `styleObjects` in application order to locate the definition that overrides a
conflicting style. Check each declaration's `condition` before treating it as active. Values are
declared CSS; verify computed styles and rendered geometry with a browser tool.

**Limits:** Browser DOM only. Cross-origin or disabled stylesheets are skipped, and rule scanning
is bounded. `unresolvedClasses` identifies classes that readable rules did not explain. Compare
`matched` with `elements.length` to detect the element limit; a partial result is not a full CSS
cascade analysis.

## `react_inspect_context`

Reads every React Context value consumed by one component.

**Input:** `id` is a required integer. `depth` is an integer from 1 to 6 and defaults to 2.

```bash
npx @genie-react/cli call react_inspect_context \
  '{"id":42,"depth":3}' --json
```

**Output (selected fields):**

```json
{
  "id": 42,
  "name": "CheckoutForm",
  "contexts": [
    {
      "name": "ThemeContext",
      "value": { "mode": "dark" },
      "provider": { "id": 12, "name": "ThemeContext.Provider" }
    },
    { "name": "AuthContext", "value": { "role": "guest" }, "provider": null }
  ]
}
```

`provider` is the closest matching Provider above the component, whose value it reads; `null` means
no Provider is mounted above it, so the value is the context default.

**Agent use:** Compare the consumed value with the expected provider value, then inspect or override
the named Context if the wrong provider or stale value explains the UI.


Name selectors use `component`; numeric `id` and `rootId` select a specific mounted instance or subtree, and `selector` is a CSS selector. Those distinct identity domains are preserved. Inspection and override actions operate on that explicit target; their receipts are not component-population filters.
