These tools belong to the `timeline` group and are available through `<Genie />`, the hub-served
script entry, or the manual `timelineCollector`. They record only after an explicit start. Events
line up by time only (`correlation: "temporal-only"`), so confirm a link with render causes. A lane
whose coverage is unavailable recorded nothing, which does not mean nothing happened. The
[optimize guide](/docs/guides/optimize#request-or-render) shows a recording end to end.

## `timeline_start`

Starts one bounded recording on a monotonic clock. It replaces the previous stopped recording.

**Input:** Required `name` is trimmed and accepts 1–120 characters. Optional `maxEvents` is an integer
from 1–10,000, default 1,000. Optional `maxDurationMs` is an integer from 1–120,000, default 30,000.
Optional `queryValues` is `hashed` (default) or `plain`; see [query strings](#query-strings).

```bash
npx @genie-react/cli call timeline_start \
  '{"name":"open checkout","maxEvents":1000,"maxDurationMs":30000}' --json
```

**Output (selected fields):**

```json
{
  "id": "timeline-EXAMPLE",
  "name": "open checkout",
  "state": "recording",
  "eventCount": 0,
  "correlation": "temporal-only",
  "clock": "performance.now"
}
```

**Agent use:** Save the returned ID, inspect each domain's `coverage`, drive the interaction, and
wait for its actual success condition before stopping. Only this response includes each lane's
coverage `detail`; read and stop responses keep the stable `code` listed under
[coverage codes](#coverage-codes).

**Limits:** One recording at a time. A concurrent start errors. Event and duration limits stop the
recording automatically. Missing browser, Query, Router, or supported development React capabilities
are explicit gaps. This records timing associations and does not prove causation. Starting replaces
retained evidence only after setup succeeds. A monotonic clock is required.

## `timeline_read`

Reads a bounded page without stopping the recording.

**Input:** Required `id` is the returned recording ID. Optional `domains` is a non-empty array of
up to four values from `request`, `query`, `react`, and `navigation`. Optional `offset` is a
nonnegative integer, default 0. Optional `limit` is an integer from 1–1,000, default 200.

```bash
npx @genie-react/cli call timeline_read \
  '{"id":"timeline-EXAMPLE","domains":["request","react"],"offset":0,"limit":200}' --json
```

**Output (selected fields):**

```json
{
  "id": "timeline-EXAMPLE",
  "state": "stopped",
  "correlation": "temporal-only",
  "events": [
    {
      "sequence": 13,
      "domain": "react",
      "type": "commit",
      "atMs": 125.1,
      "details": {
        "rendererId": 1,
        "renderDurationMs": 100.2
      }
    }
  ],
  "matchedEventCount": 1,
  "nextOffset": null
}
```

**Agent use:** Compare completed request durations with React render durations and the surrounding
Query/navigation events. Use `nextOffset` with the same filter for subsequent pages.

**Limits:** Events are ordered by observation time and sequence. Resource `startMs`, `endMs`, and
`durationMs` are separate from asynchronous observation time. React `renderDurationMs` is root
render work when known, not commit wall time or native UI time. An active report can append events;
`nextOffset: null` means caught up now. A replaced recording or a previous document's ID errors.
Each report includes coverage and truncation; absent events do not prove absent work.

A request event carries `method` and `outcome` from the app's own `fetch` and `XMLHttpRequest`
calls during the recording: `response`, `aborted`, `aborted-after-response` (the response headers
arrived, then the app or the network cancelled the body), `failed`, or `in-flight`. A request still
unanswered at stop is an `in-flight` event with `endMs: null`. `method` is `null` for a request
that bypassed Genie's observer, such as one sent through a `fetch` reference a library saved before
recording; its `outcome` then comes from timing alone: `no-response` or `unknown` across origins.
`bodyReadMs` is when the app finished reading the body (`json()`, `text()` and similar, or an XHR
`load`). `responseReceived` is `false` when a same-origin request got no response; its `durationMs`
runs until the failure. `null` means cross-origin timing without `Timing-Allow-Origin` hides it. A
redirect chain is one event under the requested URL, timed across every hop, with the final
`responseStatus`. Requests Genie makes for itself, such as reading app source files and source maps
to locate components, are left out so the lane shows only app traffic; `genieRequestsExcluded`
counts them. The app's own requests to the same files are kept. Navigation `pathChanged` and `hrefChanged` are `null` when the Router release does
not report them.

For requests to the same method and path that overlap in time, `overlappingSameEndpoint` counts the
others, `finishedAfterNewer` is `true` when a request started after this one answered first, and
`bodyReadLast` marks the one whose body the app read last. An older request with
`finishedAfterNewer: true` and `bodyReadLast: true` is the classic response race: the app most
likely applied the stale result. Which result the app put on screen is not visible to the network
lane; confirm it with the UI or the component's state.

### Query strings

Query strings can carry tokens, so by default `query` keeps parameter names and replaces each value
with a salted hash: `?q=~3f9a1c2e7b&range=~0be41f9a33`. Equal values hash alike within one page
load, so `?q=` and `?q=webhook`, or `range=7d` and `range=90d`, are told apart; an empty value stays
empty, and the salt never leaves the page. Start with `"queryValues":"plain"` to see values as sent.
Parameters named like credentials (`token`, `key`, `secret`, `password`, `signature`, `session`,
`code` and similar) stay hashed even then. `query` is `null` when the URL has none. Fragments and
URL credentials are never reported.

## `timeline_stop`

Freezes metadata, flushes pending resource timings within the recording boundary, and releases
listeners. Use `timeline_read` afterward for events.

**Input:** Required `id` is the returned recording ID.

```bash
npx @genie-react/cli call timeline_stop '{"id":"timeline-EXAMPLE"}' --json
```

**Output (selected fields):**

```json
{
  "id": "timeline-EXAMPLE",
  "state": "stopped",
  "stopReason": "manual",
  "durationMs": 280,
  "eventCount": 13,
  "truncated": false
}
```

**Agent use:** Read the stop reason and coverage, then inspect or save the frozen events as JSON.
Repeated stops return the same metadata.

**Limits:** This does not wait for pending app work. `stopReason` can also be `max-events`,
`max-duration`, or `collector-cleanup`. Hitting the event cap sets `truncated`; resource observation
still has its documented coverage limits even when that flag is false. Only one stopped recording
is retained in app memory, so save it before starting another or reloading.

## Coverage codes

Each lane reports `status` and a stable `code`. `timeline_start` adds the `detail` text once. The
text is fixed for each code, so read and stop responses lose nothing by omitting it.

| Code | Lane | Meaning |
| --- | --- | --- |
| `resource-timing-and-fetch` | request | Resource Timing joined with the app's `fetch`/XHR calls during the recording: adds `method`, `outcome` including aborts after headers, `bodyReadMs`, and in-flight requests at stop; requests seen only by those calls are added at stop; worker and non-fetch/XHR requests are absent; cross-origin detail needs `Timing-Allow-Origin`; query values are hashed unless `queryValues` is `plain`. |
| `resource-timing` | request | Finished fetch/XHR Resource Timing only; delivery can lag; aborted and failed requests can appear with `responseReceived:false`; an abort after the headers looks like a response; unfinished, worker, and non-fetch/XHR requests are absent; cross-origin detail needs `Timing-Allow-Origin`; query values are hashed unless `queryValues` is `plain`. |
| `resource-timing-flush-failed` | request | As above, but the final resource queue flush failed, so entries can be missing. |
| `no-resource-timing` | request | Browser Resource Timing is unavailable; native requests are not observed. |
| `query-cache` | query | QueryCache add, remove, and update notifications; no prior snapshot, mutation cache, payloads, or request links. |
| `no-query-client` | query | No QueryClient was supplied. |
| `react-root-commits` | react | Development React root commits with root `actualDuration`; not commit wall time, effects, or component attribution. |
| `no-react-renderer` | react | No supported development React renderer or hook; load Genie before React. |
| `tanstack-router` | navigation | TanStack Router lifecycle notifications with pathnames only. |
| `no-tanstack-router` | navigation | No TanStack Router was supplied; other routers and native navigation are not observed. |
