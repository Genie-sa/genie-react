## `react_clear_renders`

Clears render counters and starts a new causal observation window.

Genie analyses renders and effects only while something observes them: a window from this tool,
`react_profile_start`, `devtools_interaction_begin` or `verify begin`, an open `react_measure`
span, or a recording timeline. `react_profile_stop` pauses the analysis. With none open, Genie
keeps only what a later read needs about the present:
error boundary catches, document commit IDs, mount generations, Suspense and hydration state, and
the tree itself. A render or effect read made with no window open reports those commits as
`coverage.unobservedCommits` with the reason `commits-not-observed`, so an empty result never reads
as "nothing rendered". Open a window before the interaction you want to measure. A window a tool
opens starts after the page has loaded, so to observe the load itself, open the page with
`_genie_observe` in its URL (for example `?_genie=my-agent&_genie_observe`): the hook then opens a
window before React's first commit, with the largest analysis budget.

**Input:** `component` reserves analysis for one display name or a list of at most 50, matched
exactly like the read tools; `exact` defaults to `true`, and `false` matches case-insensitive
substrings. Each name is trimmed
to 1–160 characters. The older `components` key still accepts substrings and the response then lists
a `deprecations` entry naming `component`. `roots` defaults to `[]` and accepts at most 20 integer component IDs.
`budget` is optional. `fiberLimit` defaults to 250, `operationLimit` to 20000, `timeLimitMs` to 8,
`targetOperationReserve` to 4000, `targetTimeReserveMs` to 4, and `adaptive` to `true`; the numeric ranges are
50–20000, 1000–2000000, 1–500, 100–500000, and 0.5–250 respectively. `lifecycle`
defaults to `{bufferLimit:1000,targetReserve:100}`; `bufferLimit` is an integer from 100 to 20000,
`targetReserve` is an integer from 0 to 5000, and the reserve cannot exceed the buffer.

The first commit analyzed after commits nothing observed, such as the first interaction in a new
window, gets four times `timeLimitMs` and `targetTimeReserveMs`, up to their maxima, because the
analysis code runs cold; `operationLimit` still bounds its work.

The expanded maxima are opt-in. With `adaptive:true`, the call counts the components already
mounted and raises `fiberLimit`, `operationLimit`, and `timeLimitMs` by the same factor until
`fiberLimit` covers them, up to the maxima; `observationConfig.adaptiveScale` reports the factor. A
later commit that renders more components than the limit, or runs out of work, raises the budget
for the commits after it. The budget steps back down after 30 commits in a row fit it, but never
below the largest tree the window has seen. Growth cannot restore evidence skipped by the commit
that ran out. For a
one-action window, especially on a large React Native tree, discard incomplete coverage and rerun
the action from a fresh window with an explicitly larger budget.

```bash
npx @genie-react/cli call react_clear_renders \
  '{"component":"ProductCard","budget":{"fiberLimit":500,"timeLimitMs":12}}' --json
```

**Output (selected fields):**

```json
{
  "ok": true,
  "tracking": true,
  "documentCommitId": 18,
  "observation": {
    "id": "observation:2",
    "epoch": 2,
    "startedAfterDocumentCommitId": 18
  },
  "observationConfig": {
    "adaptive": true,
    "fiberLimit": 500,
    "timeLimitMs": 12
  }
}
```

**Agent use:** Drive exactly one interaction next, then join render and effect evidence by
`observation.id`. This call discards earlier counters and starts fresh retained histories, so capture
needed evidence before clearing again. Use the subsequent render and cause evidence only when its
coverage is complete and `budgetExhaustedCommits` is zero; adaptive recovery later in the window
does not repair an earlier incomplete commit.

## `react_get_renders`

Summarizes component render counts, changed inputs, timing, mount identity, and source.

**Input:** `component` is an optional exact display name; `exact` defaults to `true`, and `false` matches every name containing it, ignoring case. `componentMatch` reports which names matched. `sort` is `renders`, `updates`, `unnecessary`,
`referenceOnly`, `unstable`, or `selfTime` and defaults to `renders`. `limit` is an integer from 1 to
200 and defaults to 40. `appOnly` defaults to `true`. `nameFilter` accepts a case-insensitive
whole-name glob (1–160 characters): `*` matches any text and `?` matches one character. `excludeNames`
accepts up to 50 such globs. `minUpdates` is a nonnegative integer and defaults to 0. These selectors
combine with `component` and run before source classification and the cap.
`view` is `summary` (default) or `full`. The summary keeps counts, timing, cause kinds and names,
input evidence, and one `source` with `location` and `ownership` per component. `full` adds input
values and `deepDiff`, behavior `assessment`, `instance` details, `sourceProvenance`, and the legacy
`unnecessary`, `unstableRenders`, `forget`, and `necessity` fields.

`renders` counts committed renders: Strict Mode's second invocation, render attempts React discarded,
and renders React bailed out of are not included. A component that unmounts inside the window keeps
its counts and reports `unmounted: true`. Genie retains as many unmounted records as
`lifecycle.bufferLimit` (default 1,000); older ones are evicted, counted in
`coverage.droppedUnmountFibers`, and make the counts a lower bound.

Use `nextCursor` with `cursor` to read the remainder; pass only `cursor` and optional `limit` or
`view` on continuation calls. Pages retain the first report's ordering, counts, summary, source coverage, and
observation metadata while new commits arrive. `pagination` reports the snapshot ID, row offset,
total selected rows, and `expiresAt` in Unix milliseconds. `omittedByLimit` counts rows remaining
after the current page, and `nextCursor:null` means that selected snapshot is exhausted.

Cursors expire after five minutes or eviction by newer reports (at most three paginated snapshots
are retained). Clearing/restarting profiling or disposing tracking invalidates them. Reports with
more than 5000 candidates matching the name/update filters (before `appOnly`) fail before snapshot
construction, with a narrowing instruction. Invalid or expired cursors require a fresh call without
`cursor`.

`includeCursor` defaults to `true`. Set it to `false` for a one-shot report: the requested row limit
still applies, the summary covers all selected records, and omitted rows are not recoverable by
cursor. No snapshot is retained, `pagination.snapshotId` and `expiresAt` are null, and the 5000-candidate
snapshot limit does not apply. Background React quiet waits use this mode so polling cannot evict
an active paginated report.

Source ownership is separate from pagination. `appOnly:true` hides only components known to be
library code; components with unresolved ownership stay in the result, marked
`sourceOwnership: "unknown"`, and `filteredNote` counts them. Retry without `cursor` after source
warmup to classify them.

Both `react_get_renders` and `react_profile_report` expose `bundle` (`development`, `production`,
`mixed`, or `unknown`), `timingsBundleDependent: true`, and `countsScope: "observed-run"`.
The bundle describes registered React renderers in the app document. Timing values depend on that
bundle and instrumentation. Counts describe this measured run, subject to coverage; they are not
production estimates. Development Strict Mode behavior can differ from production. Compare runs
with equivalent conditions and check collection availability even when the bundle is `production`.

`sourceClassification` reports app, library, and unknown ownership counts for matching records
before `appOnly` and the result limit. `totalCandidates` counts that set; `evaluated` counts
completed source lookups (including unresolved results and cache hits). `complete` is true only
when every candidate has app or library evidence. Unknown ownership never counts as library.

Cold documents can exceed the source lookup budget. Genie warms the remaining sources in the
background; retry the report to check recovery. While `appOnly:true` results include unknown
ownership, `comparable` is false with `app-source-classification-incomplete`, and summary semantics
are `unknown`, because the summary may count library work. If unknowns persist after relaunch, inspect this unfiltered report and restore source
metadata or source-map access before comparing app-only measurements.

For `const FriendListRow = memo(() => ...)`, the wrapper does not retain the variable's name.
Genie uses an explicit wrapper `displayName`, then the inner function's name, and finally source
information when available. To preserve anonymous memo binding names automatically, add the

**Agent use:** Optimize the highest cumulative cost only after the exact changed path and complete
coverage explain the render; request `view:"full"` for the changed values and `deepDiff` paths.
Compatibility counts such as `unnecessary` are not proof that a render is safe to remove.

Props, `children` included, cause a render only for components that can skip it on equal props:
`memo` components and classes that extend `PureComponent` or define `shouldComponentUpdate`. Any
other component lists its own state, context, or store changes first, otherwise `parent`, and its
changed props and `children` follow as observed inputs. State or context that received a new object
with equal contents does not make a render `necessary` and counts toward `noObservedInputChange`.
React renders a component on its own only for an input it saw change, so a render with no observed
trigger and no rendered parent gets an `unknown` cause instead: `no-observable-fiber-input-change`
for inputs Genie cannot read, such as `forceUpdate`, or `unclassified-hook-changed` with `hookIndex`
for a hook it cannot classify, such as `useDeferredValue`. Neither counts toward
`noObservedInputChange`. With complete coverage, a render of those components whose changed props
were all reference-only or new functions counts toward `functionIdentityPropRenders` when any function
changed identity, usually an inline callback, and toward `referenceOnlyPropRenders` otherwise.
`undeterminedReferencePropRenders` counts renders whose reference changes a partial scan or a
truncated diff could not classify. Genie never calls a custom `shouldComponentUpdate`, so such a class
is counted as if it compared props shallowly.

## `react_render_causes`

Returns joinable render events and their observed causes.

For a single identified Query observer, Genie omits an inferred cause when its complete current
notification policy excludes every changed subscribed field. `notificationPolicyCheck.status`
is `matched` with `changedSubscribedFields` when a subscribed field changed, or `unavailable`
with a reason when the policy, identity, or field comparison cannot be checked. The basis is
`current-effective-policy`: this checks compatibility with current options, not historical
notification delivery. Dynamic and private auto-tracked policies remain unavailable. Implicit
`error` subscriptions from `throwOnError` are included; recorded exact deliveries take precedence
and are never removed by this check.

**Input:** `commit` and `afterCommit` are optional nonnegative integers and are mutually exclusive.
Both match the `documentCommitId` shown on every event.
`component` is an optional exact display name; `exact` defaults to `true`, and `false` matches every name containing it, ignoring case. `componentMatch` reports which names matched. `limit` is an integer from 1 to 500 and defaults to 100.
`appOnly` defaults to `true`. `view` is `summary` (default) or `full`; the summary names each cause,
while `full` adds input values, `deepDiff`, Query notification details, `assessment`, `instance`,
and source attribution.

## `react_component_cohort`

Reports lifecycle outcomes for every matching component instance in the current observation.

**Input:** `component` is a required non-empty string. `exact` defaults to `true`. `limit` is an
integer from 1 to 200 and defaults to 50. `view` defaults to `summary`, which states the value most
instances share once under `shared` (component, source, parent, rendering state and the common
`logicalPath` prefix) and keeps per row only its status, mount id, key, index, the rest of its path,
host selector and commit; a row lists a shared field only where its value differs. `view:"full"`
returns every instance with its full descriptor and source provenance.
`appOnly` defaults to `false`; set it to `true` to hide instances known to be library code.
Ownership includes mounted instances and cached unmount provenance. Unknown ownership stays visible
and lowers coverage. `documentCommitId` marks the captured traversal;
`attribution.status: "stale"` means commits or a clear raced source lookup.

Each instance also reports its current `renderingState`, independently of recorded updates:

- `mounted-rendering`: mounted and eligible to render; it may have stayed idle during the observation.
- `mounted-frozen`: retained under a registered `react-freeze` boundary whose primary subtree has committed suspension.
- `mounted-hidden`: retained under React Offscreen hiding, without proven `react-freeze` origin (for example, Activity).
- `mounted-unknown`: the boundary state is unavailable.
- `unmounted`: an actual unmount was observed during this observation.

Enable freeze identification in your development entry, alongside the Genie hook:

```ts
import 'genie-react/react-freeze'
```

The optional adapter imports and registers the actual `Freeze` export from `react-freeze` 1.x.
It also identifies the same export used internally by `react-native-screens` when
`enableFreeze(true)` suspends a screen. No component-name heuristic is used. If your workspace
resolves multiple copies, register the app's public import too:

```ts
import { registerReactFreeze } from 'genie-react/react-freeze'
import { Freeze } from 'react-freeze'

registerReactFreeze(Freeze)
```

Use the same `react-freeze` package version/resolution as your navigation dependency. A copy
that was not registered remains generic hidden evidence; the adapter never guesses its identity.
`coverage.freezeDetection` reports whether the adapter is enabled. Frozen status requires
committed suspension, so a delayed or pending freeze request does not count yet. Suspense
fallback components remain eligible to render. Thawing preserves mount identity; actual
unmounting produces a tombstone. None of these states proves effect or Query observer subscriptions.

Each instance reports `reactVisibility` independently of its lifecycle status:

- `hidden`: a committed React Offscreen ancestor has hidden state, including Activity or suspended content.
- `not-hidden`: no hidden React Offscreen ancestor was observed; this does not prove CSS or native screen visibility.
- `unknown`: visibility cannot be established, including unmounted tombstones or incomplete boundary state.

A hidden instance remains in the mounted cohort with its mount identity. Revealing it preserves
that identity; an observed full unmount produces an `unmounted` entry. React visibility does not
prove which navigation or freeze mechanism hid the subtree. Activity can clean up effects and
subscriptions while preserving state, so disappearing observers alone do not establish a full
unmount. `react-freeze` uses Suspense, and generic hidden evidence cannot establish its origin.

## `react_effect_audit`

Ranks effect schedules and reports dependency, cleanup, hotness, and ownership evidence.

**Input:** `component` is an optional exact display name; `exact` defaults to `true`, and `false` matches every name containing it, ignoring case. `componentMatch` reports which names matched. `onlyHot` defaults to `false`. `appOnly` defaults to

effects whose declaration is unresolved stay, with `provenance.ownership: "unknown"`. `packageName` is an optional trimmed string of 1–214 characters and requires
`appOnly:false`. `minUpdates` is an integer from 1 to 1000 and defaults to 3. Legacy `minFireRate`
is from 0.1 to 1 and defaults to 1. Preferred `minScheduleRate` is optional, is from 0.1 to 1, and
takes precedence. `limit` is an integer from 1 to 200 and defaults to 40.

`index` counts the component's effect hooks in call order and stays stable across renders.
`hookIndex` is the flat hook index `react_inspect_component` reports, and `customHooks` is the same
chain, so one effect is addressed the same way in every tool. React-internal effects pushed without a
hook, such as `useSyncExternalStore`'s snapshot check, are not reported.

Each effect is attributed to the hook call that declared it, located with the same hook inspector
React DevTools runs when you select a component (one shadow render per component type). `source`
is that call (`role: "hook-callsite"`), so an effect inside a library hook is library-owned even in
an app component, and `react_effect_timeline` reports the same ownership.

`hotness` answers "does this effect run more often than its inputs justify?". An effect with
dependencies is `hot` when it re-ran at least `minUpdates` times while every dependency that changed
identity kept equal contents (`basis: "reference-only-reruns"`), for example a new object literal on
each render. Re-runs driven by a changed value are not hot (`value-change-reruns`). When the changed
dependencies cannot be compared, such as functions, the label is `insufficient-data`
(`dependency-values-not-compared`). An effect without a dependency array is hot when it was
scheduled on at least `minScheduleRate` of updates (`no-dependency-array`).

**Agent use:** Inspect the exact hook callsite and changed dependency before editing the effect. A
schedule does not prove execution or cleanup timing, and unknown ownership must not be assigned to
the app.

States: `fallback` is the committed fallback; `transition-pending` means the old content stays on
screen while an uncommitted render of the boundary waits, so its `stateEvidence` is `inferred`;
`dehydrated` is server HTML that has not hydrated; `content` shows the children. A blocker's

screen awaited it before it committed. `kind` is `lazy`, `use`, `data-library`, `server-io`,
`server-stream`, `asset` (a stylesheet), or `unknown`, and `kindEvidence` says whether React
recorded that mechanism (`exact`) or a stack frame points to it (`inferred`). A promise thrown

with the Query collector, a promise `useSuspenseQuery` threw is named by its query (`query` with
`queryHash` and `queryKey`, `kind: "data-library"`, `kindEvidence: "inferred"`), joined through the
component under the boundary whose render started that query's fetch, while it is still fetching.

then settled ones by duration, with the RSC stream entry, which spans the whole request, after the
awaits it carried. `blockersOmitted` counts the shorter ones past `blockerLimit`.

settled last, so `coverage.serverAwaits` is `last-settled-per-await` whenever server I/O is listed:
a read that ran beside another can be absent. Measure a waterfall fix by the critical path, from the
earliest start to the latest end. `hydration` is `client-rendered` when React discarded the
boundary's server HTML; see [`react_hydration`](#react_hydration).

Suspense boundaries, so a framework overlay bundling its own production React, as Next.js does in
development, does not count. React 19.2 and later development builds are `available`. React 19.0
and 19.1 are `partial`: `use()` and `React.lazy` are recognized, but client promises carry no name
or timing. React 18 and production builds are `unavailable`; boundaries and states are still listed,
and `blockerStatus` is `unavailable`. Development and production roots that both hold boundaries
make it `partial` with `reason: "some-roots-without-debug-info"`. Images and fonts are not observed.

**Agent use:** Check `capability` first, then read the waiting boundaries. Fix the pending blocker
with `exact` evidence; treat `inferred` and `unknown` as leads. `not-observable` means the boundary
waits but React kept nothing to read, and `unrecorded` means a fallback committed earlier without
debug information. Read again when `coverage.changedDuringRead` or `coverage.commitScheduled` is
`true`. After the content appears, the same boundary lists what it awaited and for how long, which
verifies that a change shortened or removed the wait.

## `react_profile_start`

Clears render counters and starts a profiling observation.

**Input:** `component` and `exact` select the components to reserve analysis for, exactly as in
`react_clear_renders`; the older `components` key still accepts display-name substrings. `roots` defaults to `[]` and accepts at most 20 integer component IDs.
`budget` is optional. `fiberLimit` defaults to 250, `operationLimit` to 20000, `timeLimitMs` to 8,
`targetOperationReserve` to 4000, `targetTimeReserveMs` to 4, and `adaptive` to `true`; the numeric ranges are
50–20000, 1000–2000000, 1–500, 100–500000, and 0.5–250 respectively. `lifecycle`
defaults to `{bufferLimit:1000,targetReserve:100}`; `bufferLimit` is an integer from 100 to 20000,
`targetReserve` is an integer from 0 to 5000, and the reserve cannot exceed the buffer.

The first commit analyzed after commits nothing observed, such as the first interaction in a new
window, gets four times `timeLimitMs` and `targetTimeReserveMs`, up to their maxima, because the
analysis code runs cold; `operationLimit` still bounds its work.

The expanded maxima are opt-in. With `adaptive:true`, the call counts the components already
mounted and raises `fiberLimit`, `operationLimit`, and `timeLimitMs` by the same factor until
`fiberLimit` covers them, up to the maxima; `observationConfig.adaptiveScale` reports the factor. A
later commit that renders more components than the limit, or runs out of work, raises the budget
for the commits after it. The budget steps back down after 30 commits in a row fit it, but never
below the largest tree the window has seen. Growth cannot restore evidence skipped by the commit
that ran out. For a
one-action profile, especially on a large React Native tree, discard incomplete coverage and rerun
the flow from a fresh profile with an explicitly larger budget.

```bash
npx @genie-react/cli call react_profile_start \
  '{"component":"SearchResults","lifecycle":{"bufferLimit":2000,"targetReserve":200}}' --json
```

may be evicted at capacity; opening fails if all 20 are open. Reload/Fast Refresh invalidates handles.

## `react_renders_since`

Reads the labelled span's owned commits.

**Input:** `handle` is required (1–100 characters), `close` defaults to
`false`, `component` optionally filters by exact display name (set `exact` to `false` for a substring), `appOnly` defaults to `true`, and `limit`
is an integer from 1 to 200 (default 40). Set `close:true` after driving the interaction and waiting
for commits to settle. Re-reading a closed span preserves its captured counts.

```bash
npx @genie-react/cli call react_renders_since '{"handle":"<returned handle>","close":true}' --json
```

**Output (selected fields):**

```json
{"label":"open checkout","commitIds":[19,21],"commits":2,"excludedCommits":1,"coverage":{"complete":true,"semantics":"exact"}}
```

**Agent use:** Compare labelled counts without clearing another span's evidence.
The response carries `label`, disjoint `commitIds`, `excludedCommits` owned by newer spans,
`components`, `summary`, `sourceClassification`, and `coverage`. Counts are frozen before source
lookup. `omittedByLimit` identifies rows outside the selected page; the summary covers all selected
components. Global clear does not erase span evidence. A span retains at most 500 components and
1000 commits; hitting the commit cap closes it. Collection and retention losses make coverage
incomplete. Unresolved source ownership also makes an app-only report incomplete; use
`appOnly:false` to inspect all retained records. `attribution:"temporal-only"` explicitly means
these counts do not prove which interaction caused a commit.

## `react_quiesce`

Waits until React document commits have remained unchanged for the requested interval and React
holds no pending work.

**Input:** `idleMs` is an integer from 100 to 5000 (default 500); `timeoutMs` is an integer from
1 to 60000 (default 10000). Unknown fields are rejected. The CLI transport allows the requested deadline.

```bash
npx @genie-react/cli call react_quiesce '{"idleMs":500,"timeoutMs":10000}' --json
```

**Output (selected fields):**

```json
{
  "ok": true,
  "outcome": "idle",
  "elapsedMs": 750,
  "observedCommits": 3,
  "documentCommitId": 21,
  "renderCollection": "available",
  "pendingWork": {
    "documentCommitId": 21,
    "scheduledRoots": 0,
    "suspendedBoundaries": 0,
    "boundaries": [],
    "scanTruncated": false
  }
}
```

**Agent use:** Clear, drive one UI interaction, quiesce, then read the render report. Outcomes are
`idle`, `timed-out`, or `unavailable`; `observedCommits` counts increases between valid samples,
excluding commits before the first sample. A missing collector, changed document, or counter reset
cannot prove idle. Historical late-hook degradation remains visible but can establish a new quiet
interval. Failed samples restart the quiet interval; silent requests respect the overall deadline.
Tool-catalog refreshes in the same document preserve the wait. Add `--fail-on-result-error` for a
nonzero exit on a result with `ok:false`.

Once commits are quiet, quiesce reads [`react_pending_work`](#react_pending_work): a pending or
suspended transition, a Suspense boundary showing its fallback, or server HTML React has not hydrated
keeps the outcome from `idle`, and
a timeout names the blocking work in `reason`. `pendingWork` is `null` when the app runtime predates
that tool; idle then covers commits only. Quiesce does not observe timers, promises that never reach
React, query freshness, or continuous canvas/native frames.

## `react_pending_work`

Reports React work that has not committed yet.

**Input:** none. Unknown fields are rejected.

```bash
npx @genie-react/cli call react_pending_work '{}' --json
```

**Output (selected fields):**

```json
{
  "documentCommitId": 42,
  "scheduledRoots": 1,
  "suspendedBoundaries": 1,
  "dehydratedBoundaries": 0,
  "boundaries": [{ "boundaryId": 17, "boundaryName": "Suspense", "state": "fallback" }],
  "scanTruncated": false
}
```

**Agent use:** `scheduledRoots` counts mounted roots with uncommitted or suspended updates, such as a
transition waiting on data. `suspendedBoundaries` counts Suspense boundaries showing a fallback and
`dehydratedBoundaries` counts server-rendered boundaries React has not hydrated yet; these are the
boundaries `react_suspense` reports as `fallback` and `dehydrated`, and boundaries inside a hidden
`Activity` are not counted. Boundaries held open by `react_toggle_suspense_fallback` are excluded.
`boundaries` lists at most 20 of them with their `state`. `scanTruncated: true` means the fiber scan stopped at its limit, so the boundary count is a
lower bound. `react_quiesce` and `devtools_wait` read this tool before they report React idle.
