The JSON examples below show selected fields from the full response.

These tools exist when the app registers the [Redux collector](/docs/getting-started/install#redux).
To find the action behind a render, read the `external-store` cause from `react_render_causes`: its
`redux` field names the actions and grades the link. The history keeps the last 500 records by
default; pass `historyLimit` (1 to 5000) to `reduxCollector` to keep more. Each record holds a
depth-bounded copy of its action, so a larger history costs memory in the page.
When a component's first render in a window has no earlier render to compare with, Genie still
grades it `exact` if React had no pending work when the window opened: the window start then
bounds the actions. An `inferred` link never lists an action from before the window.

The collector supports Redux 4 and 5 and Redux Toolkit 1.9 and 2, with react-redux 8 and 9 for the
render join. It does not record dispatches that bypass the wrapped `dispatch`, such as sagas, epics
and the RTK listener middleware; their state changes appear as `unrecorded-change`. The mutation check
compares plain objects and arrays only, and skips frozen state. Pass `{ detectMutations: false }` to
`reduxCollector` to turn the check off.

RTK Query dispatches its own actions for every query a component subscribes to, often hundreds per
interaction. The history leaves them out so they cannot evict the app's actions, and counts them in
`coverage.libraryActions` instead. This covers actions whose type starts with an RTK Query
`reducerPath`, the anonymous thunks that dispatch only those, and unrecorded changes that touch only
RTK Query slices. Render causes still name these actions. Pass `{ recordLibraryActions: true }` to
`reduxCollector` to keep them as records.

```ts
reduxCollector(store, { name: 'app', historyLimit: 2000, recordLibraryActions: true })
```

## `redux_actions`

Lists recorded dispatches, oldest first, with the slices each one changed and an in-place mutation
check.

**Input:** `storeId` is needed only when the app collects several stores. `type` keeps one exact
action type and `typePrefix` keeps types starting with it. `slice` keeps records that changed that
top-level slice or mutated something under it. `kinds` keeps record kinds (`action`, `thunk`,
`unrecorded-change`, `mutation-outside-dispatch`). `mutationsOnly` defaults to false. Omit
`afterSequence` to read the latest `limit` records (1 to 200, default 50); pass a previous
`nextAfterSequence` to read forward. `matched` counts the retained records that match the filters;
with `afterSequence` it counts only those after it: this page and the newer matches still to read.
`view` defaults to `summary`; `full` adds each action's bounded
`payload`, the render events that named it as exact, and Genie's own time.

```bash
npx @genie-react/cli call redux_actions '{"typePrefix":"reports/","view":"full"}' --json
```

**Agent use:** Proves which actions ran, what they carried, and what the reducers made of them.
`rootStateChanged: false` means no Redux subscriber re-rendered. `mutation.status: "detected"` means
existing state objects changed in place during that dispatch, the mark of a reducer that mutates and
returns the same state; fix the reducer at the reported path. A thunk's actions name it as
`parentActionId`, so an out-of-order `RECEIVED` can be traced to the thunk that started it.

`none-detected` covers only the objects the bounded scan compared; `scanTruncated: true` says some
were not. An `unrecorded-change` is a state change no recorded dispatch explains, such as middleware
dispatching on its own; `coverage.unrecordedChanges` counts them. `coverage.evictedRecords` counts
records the bounded history dropped; when it grows during one interaction, raise `historyLimit`.

## `redux_state`

Reads the current state, or one path in it, depth-bounded like `query_get`.

**Input:** `storeId` is needed only when the app collects several stores. `path` is an optional
array of keys and indexes, such as `["reports","notes"]`; omit it for the root. `depth` is from 1 to
6 and defaults to 3. `where` selects entries of the container at `path` whose `field` (a key or a
path array) `equals` a string, number, boolean or null, instead of returning the container.

```bash
npx @genie-react/cli call redux_state '{"path":["reports","notes"],"where":{"field":"id","equals":"note-1"}}' --json
```

**Output (selected fields):**

```json
{
  "store": { "storeId": "redux-store:1", "name": "app" },
  "path": ["reports", "notes"],
  "found": true,
  "selection": {
    "matchCount": 1,
    "scanned": 1,
    "scanTruncated": false,
    "containerFound": true,
    "matches": [
      {
        "path": ["reports", "notes", 0],
        "value": { "id": "note-1", "text": "Spike caused by the billing migration" }
      }
    ]
  },
  "topLevelKeys": ["session", "ui", "projects", "issues", "reports"],
  "asOfSequence": 147
}
```

**Agent use:** Confirms what the store holds after an action, such as a note that reached the state
while the screen did not change. `asOfSequence` is the latest `redux_actions` record when the state
was read. A wrong path returns `found: false` with `topLevelKeys` to correct it.
