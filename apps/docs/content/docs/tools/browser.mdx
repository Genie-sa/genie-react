title: Browser metrics
description: Measure page memory and frame performance around a real browser flow.
icon: Monitor
---

The JSON examples below show selected fields from the full response.

These are page-wide signals, not React-only measurements. Repeat the same browser or device flow
for every before-and-after sample.

## `browser_get_memory`

Reads the current page-wide JavaScript heap estimate exposed by Chromium.

**Input:** No fields; pass `{}`.

```bash
npx @genie-react/cli call browser_get_memory '{}' \
  --session logical-review --json
```

**Output (selected fields):**

```json
{
  "supported": true,
  "usedJSHeapSize": 24576000,
  "totalJSHeapSize": 36700160,
  "jsHeapSizeLimit": 4294705152,
  "precision": "possibly-quantized",
  "note": "JavaScript heap reported by the browser, not React-specific memory. Chromium rounds these values into coarse buckets and caches them for up to 20 minutes unless it runs with --enable-precise-memory-info, so an unchanged reading does not show an unchanged heap. Use browser_measure_memory to compare."
}
```

**Agent use:** Prefer `browser_measure_memory` for before/after comparisons. Compare
`usedJSHeapSize` across runs only when the browser was launched with
`--enable-precise-memory-info`; by default Chromium reported the same 10,000,000 bytes before and
after allocating about 40 MB. If either sample is unsupported or from a different document, do not
claim a memory improvement.

**Limits:** This is an instantaneous reading from non-standard Chromium `performance.memory`.
`precision` is `possibly-quantized` in a browser and `runtime-reported` on React Native. It covers the whole page, not one React component. Firefox, Safari,
React Native, and runtimes without numeric heap fields return `supported:false` with a note; absent
fields are not zero. The call creates no subscription and needs no cleanup.

## `browser_measure_memory`

Requests a page-wide memory estimate with per-realm attribution when the browser supports it.

**Input:** No fields; pass `{}`.

```bash
npx @genie-react/cli call browser_measure_memory '{}' \
  --session logical-review --json
```

**Output (selected fields):**

```json
{
  "supported": true,
  "bytes": 28400000,
  "breakdown": [
    {
      "bytes": 21000000,
      "attribution": [
        { "url": "https://app.test/checkout", "scope": "Window" }
      ],
      "types": ["JavaScript", "DOM"]
    }
  ],
  "note": "Page-wide browser memory estimate across all realms (JS heap, DOM, etc.), not React-specific memory. The browser may delay sampling."
}
```

**Agent use:** Compare `bytes` and the same attribution scopes across repeated, controlled flows;
when `supported:false`, fall back to `browser_get_memory` and label the weaker evidence.

**Limits:** `performance.measureUserAgentSpecificMemory()` requires a Chromium-based browser and a
cross-origin-isolated page with COOP `same-origin` and COEP `require-corp`. Sampling can be delayed.
Chromium can expose the method yet refuse it, for example in headless Chromium; the result is then
`supported:false` with the browser's reason in `note`. The total includes all page realms, JS heap,
and DOM memory, not one component. The call leaves no ongoing sampler.

## `browser_fps`

Samples page-wide animation-frame health for one fixed time window.

**Input:** `durationMs` is an optional integer from 250–10,000 and defaults to 5,000.

```bash
npx @genie-react/cli call browser_fps '{"durationMs":5000}' \
  --session logical-review --json
```

**Output (selected fields):**

```json
{
  "durationMs": 5004,
  "frames": 299,
  "avgFps": 59.8,
  "worstFrameMs": 34.2,
  "longFrames": 0,
  "droppedFrames": 1,
  "refreshRate": 60,
  "hidden": false,
  "visibility": {
    "startedHidden": false,
    "endedHidden": false,
    "hiddenDuringSample": false
  },
  "throttleState": "none-detected",
  "calibration": {
    "method": "frame-interval-distribution",
    "confidence": "high",
    "sampleCount": 299,
    "intervalMs": { "p10": 16.6, "p50": 16.7, "p90": 16.8 },
    "modesHz": [60]
  },
  "refreshRateModes": { "firstHalfHz": 60, "secondHalfHz": 60 },
  "comparable": true,
  "notComparableReasons": [],
  "verdict": "smooth"
}
```

**Agent use:** Drive the same scroll, animation, or interaction during each sample and compare only
runs with `comparable:true`; otherwise fix visibility or sampling conditions and repeat the run.

**Limits:** The call blocks for its sampling window, so start or drive the interaction from browser
automation before or concurrently with it. It measures page-wide main-thread frame pacing, not
React work alone. A tab hidden at start errors. Hiding it during sampling, sparse calibration, or a
refresh-rate mode change sets comparability evidence that must be read. The internal timeout ends a
stalled sample; no animation-frame subscription remains after the result.

## `browser_visibility`

Reports whether the document is visible now and how often it was hidden since Genie started.

**Input:** none.

```bash
npx @genie-react/cli call browser_visibility '{}' --session logical-review --json
```

**Output (selected fields):**

```json
{
  "source": "document",
  "state": "visible",
  "hiddenTransitions": 1,
  "hiddenMs": 4120
}
```

**Agent use:** Compare `hiddenTransitions` between two reads to tell whether the app was hidden in
between; `verify` refuses a window with a hidden interval. `source` is `document` in a browser,
`app-state` on React Native when `startGenie` received `AppState`, and `unavailable` when there is no
visibility signal.
