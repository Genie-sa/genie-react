title: Plugins
description: Discover, read, and emit TanStack DevTools plugin events.

The JSON examples below show selected fields from the full response.

The examples ran against `/lab` in `apps/demo`, whose cart publishes `cart-devtools` events. Event
types and their effects belong to the app or plugin, so read live traffic before you emit anything.

## `plugin_list`

Lists plugin channels discovered from traffic or declared by the Genie provider.

**Input:** No fields; pass `{}`.

```bash
npx @genie-react/cli call plugin_list '{}' \
  --session logical-review --json
```

**Output (selected fields):**

```json
{
  "plugins": [
    { "pluginId": "cart-devtools", "eventCount": 3 },
    { "pluginId": "metrics-devtools", "eventCount": 4 }
  ]
}
```

**Agent use:** Pick the `pluginId` that owns the behavior, then read its events before deciding
whether an emit is safe.

**Limits:** A channel appears after its first event. A channel declared through the Genie provider
appears earlier with `eventCount:0`, which means no buffered traffic, not an inactive plugin. A reload
clears the buffers.

## `plugin_get_events`

Reads the newest buffered events for one plugin channel, oldest first.

**Input:** `pluginId` is a required string. `limit` is an optional integer from 1 to 200, default 50.

```bash
npx @genie-react/cli call plugin_get_events \
  '{"pluginId":"cart-devtools","limit":100}' --session logical-review --json
```

**Output (selected fields):**

```json
{
  "events": [
    {
      "type": "cart-devtools:cart-updated",
      "payload": {
        "items": [{ "id": "item-1", "name": "Tea", "price": 4 }],
        "total": 4
      },
      "ts": 1794783002084
    }
  ]
}
```

**Agent use:** Match the event type and payload to what the UI shows. When order matters to the
diagnosis, confirm it with runtime or browser evidence.

**Limits:** Each plugin keeps its latest 200 events, with payloads cut at depth 3. An unknown ID
returns `events:[]`; use `plugin_list` to tell a wrong ID from a quiet channel. Nested synchronous
dispatch can record a response before its request, so array order alone does not prove cause.

## `plugin_emit`

Emits one event on the live TanStack DevTools bus.

**Input:** `pluginId` and `type` are required strings. `payload` is optional and accepts any value.

```bash
npx @genie-react/cli call plugin_emit \
  '{"pluginId":"cart-devtools","type":"refresh","payload":{"source":"agent-check"}}' \
  --session logical-review --json
```

**Output (selected fields):**

```json
{
  "ok": true
}
```

**Agent use:** After `ok:true`, read `plugin_get_events` and check the screen. If the plugin defines
a reset event, send it afterwards.

**Limits:** A bare `type` becomes `pluginId:type`, here `cart-devtools:refresh`. `ok:false` means no
DevTools bus was present, not that a plugin ignored the event. Listeners can change app or external
state, and an emit cannot be taken back.
