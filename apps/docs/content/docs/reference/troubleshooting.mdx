title: Troubleshooting
description: Fix connection, targeting and empty-result problems.

---

Start with `doctor` from the app folder. With `--live` it also checks the running hub and app, and
prints a fix for each failure:

```bash
npx @genie-react/cli doctor --live
```

## The tab never becomes ready

```bash
npx @genie-react/cli status --session my-agent --wait 15000
```

`not_connected` with `registeredTabs: 0` means no tab reached the hub. Check that the page loads
Genie (the Vite plugin, `<GenieScript />` or the client script), then reload it. Run the CLI from the
app folder so it finds the right hub.

## The hub refuses the connection

`bridge_rejected` means the hub refused the agent token: it restarted, another hub answered, or the
CLI is older than `genie-react`. Run from the app folder with matching versions.

The hub accepts pages only from the dev server's origin and loopback. Allow a tunnel or custom host
with `genie({ allowedOrigins: [...] })` on Vite, `registerGenie({ allowedOrigins: [...] })` on
Next.js, or `GENIE_ALLOWED_ORIGINS` for `genie-react hub`.

## Commands land on the wrong tab

`SESSION_AMBIGUOUS` means several tabs match, and `SESSION_CLAIMED` means another agent uses them.
Open your own tab with `agent-browser --session <name> open <url>` and pass `--session <name>`.

## Query or Router tools are missing

Render `<Genie />` inside the providers, or pass it `queryClient` and `router`. On Next.js, register
the Query collector as [install](/docs/getting-started/install#nextjs) shows.

## Renders are always empty

Open a window before the action; otherwise reads report `commits-not-observed`. If they stay empty
with a window open, the DevTools hook loaded after React. Use the Vite plugin, or import
`genie-react/hook` before React.

## A result is incomplete

Each `coverage.incompleteBecause` entry names the gap and the next step.

## A script cannot parse the output

Add `--json`, or set `GENIE_OUTPUT=json` for the whole script.
