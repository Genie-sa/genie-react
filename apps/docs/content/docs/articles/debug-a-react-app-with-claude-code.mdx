To debug a React app with Claude Code, give it two tools it can run from the terminal. A browser
driver acts on the page, and Genie reports what React did and decides whether the fix held. You
install Genie in the app, run `npx genie-react init` to add the skill, and ask Claude Code for the
outcome, such as "find out why this re-renders, fix it, and verify the fix."

This page follows one real bug in the Meridian Ops dashboard (`apps/realworld-dashboard` in this
repo). Ticking one order's checkbox re-rendered the sidebar. Each step shows the commands from the
Genie skill's loop, as run in this repo, with their real output. The full log is in the
[evidence file](https://github.com/Genie-sa/genie-react/blob/main/docs/article-evidence/debug-a-react-app-with-claude-code.md).

## Install Genie and the skill

From the app folder, install both packages:

```bash
pnpm add -D genie-react @genie-react/cli
```

You need both. `genie-react` holds the runtime, and `@genie-react/cli` holds the `genie-react`
command. `npm view` shows that only the CLI package has a bin:

```text
$ npm view genie-react@1.0.2 bin

$ npm view @genie-react/cli@1.0.2 bin
{ 'genie-react': 'dist/cli.js' }
```

The dashboard already lists both as dev dependencies, so the run starts at `init`. Trimmed to the
artifacts, with the checkout path shown as `<checkout>`:

```text
$ npx genie-react init
ok setup_completed: Setup changes are recorded in artifacts.
  framework: tanstack-router
  artifacts[7]:
    - {kind:vite_config,status:already,path:<checkout>/apps/realworld-dashboard/vite.config.ts}
    - {kind:root_route,status:already,path:<checkout>/apps/realworld-dashboard/src/routes/__root.tsx}
    - {kind:gitignore,path:<checkout>/apps/realworld-dashboard/.gitignore,status:applied}
    - {kind:agent_skill,path:<checkout>/apps/realworld-dashboard/.agents/skills/genie/SKILL.md,status:applied}
    - {kind:agent_skill,path:<checkout>/apps/realworld-dashboard/.agents/skills/genie/APP_TOOLS.md,status:applied}
    - {kind:agent_skill,path:<checkout>/apps/realworld-dashboard/.agents/skills/genie/EVIDENCE.md,status:applied}
    - {kind:agent_skill,path:<checkout>/apps/realworld-dashboard/.claude/skills/genie,status:applied,link:symlink}
```

`init` writes the skill to `.agents/skills/genie` and links `.claude/skills/genie` to it, which is
where Claude Code looks for project skills. In the Claude Code session that ran these commands, the
skill showed up as `genie` right after `init`. The Vite config and root route already had Genie, so
`init` left them alone. [Install and connect](/docs/getting-started/install) lists what `init`
changes in other setups.

The installed skill calls the CLI as `node_modules/.bin/genie-react`, so the commands below use that
path. The README says a wrapper such as `npx` or `pnpm exec` adds up to 350 ms to every call.

## Ask for the outcome

Start the dev server, open the app with an agent-browser session, and check that Genie is
connected. Use the same session name for both tools:

```bash
agent-browser --session art-l6 open http://127.0.0.1:5216/orders
node_modules/.bin/genie-react status --session art-l6 --wait 15000
```

`status` printed `connected: true` and `ready: true`. Then name the interaction and what you want:

> Ticking an order's checkbox on the Orders page re-renders the sidebar. Find out why, fix it, and
> verify the fix.

The skill gives the agent a loop: open a window, act once, read the evidence, fix, and verify.

## Reproduce once and read the render cause

The agent opens a render window for `SidebarNav`, ticks one row, and waits for React to go idle:

```bash
node_modules/.bin/genie-react call react_clear_renders '{"component":"SidebarNav"}' --session art-l6
agent-browser --session art-l6 find role checkbox check --name 'Select SO-106000'
node_modules/.bin/genie-react call react_quiesce '{"idleMs":500,"timeoutMs":10000}' --fail-on-result-error --session art-l6
node_modules/.bin/genie-react call react_render_causes '{"component":"SidebarNav","limit":20}' --session art-l6
```

The summary names one render, graded unnecessary, from an external store (trimmed):

```text
SidebarNav #8946769199146 {renderEventId:render:10:1,documentCommitId:10,mountId:mount:1,necessity:unnecessary,necessityReason:output-unchanged,inputEvidence:none-observed,source:{location:/src/layout/app-shell.tsx:38:9,role:element-callsite,ownership:app}}
  ← external-store inferred anonymous-external-store
coverage:
  complete: true
```

`output-unchanged` means the render wrote nothing to the DOM. The same call with `"view":"full"`
says which store field changed (selected fields of the cause):

```text
← external-store inferred {reason:external-store-snapshot-changed,...,selectionEqual:false,subscriptionFired:true,...,changedFields:[selectedOrderIds],...,selector:null,equality:object-is,...}
```

The sidebar never shows the selection, yet a change to `selectedOrderIds` re-rendered it.
`selector:null` says the component reads the store with no selector.

## Find the line

`source` points at `app-shell.tsx:38`, where `AppShell` renders `<SidebarNav>`. The component lives
in `src/layout/sidebar-nav.tsx`, and it reads the zustand store like this:

```tsx title="src/layout/sidebar-nav.tsx"
const { recentlyViewed } = useWorkspaceStore()
```

Calling a zustand hook with no selector subscribes the component to the whole store. Ticking a
checkbox writes a new `selectedOrderIds` set, so every subscriber without a selector renders.

## Write the claims before the fix

Before changing code, the agent records a failing verdict. `begin` fixes the claims:

- `render SidebarNav max 0` says the sidebar must not render.
- `render BulkActionBar min 1` says the toolbar that shows the selection must render. This is the
  positive control. If the click misses, this claim fails the run instead of leaving only a refusal.
- `boundaries clean` says no error boundary catches anything.

```bash
agent-browser --session art-l6 reload
node_modules/.bin/genie-react verify begin --session art-l6 --name 'select one order' \
  --claim 'render SidebarNav max 0' --claim 'render BulkActionBar min 1' --claim 'boundaries clean'
agent-browser --session art-l6 find role checkbox check --name 'Select SO-106000'
node_modules/.bin/genie-react verify end vfy_0f82808b-bf71-4fd4-a5b5-b9fd1e987a52 --session art-l6
```

Trimmed to the verdict and claim lines:

```text
fail vfy_0f82808b-bf71-4fd4-a5b5-b9fd1e987a52 "select one order"  8 commits, quiet after 1235 ms (react, query, router)
  1 fail render SidebarNav max 0  {renders:1,mounts:0,updates:1,remounts:0,semantics:exact,instances:1,activeInstances:1}
  2 pass render BulkActionBar min 1  {renders:1,mounts:0,updates:1,remounts:0,semantics:exact,instances:1,activeInstances:1}
  3 pass boundaries clean  {caughtDuringWindow:0,caughtAtEnd:0}
```

The command exited 1.

## Apply the fix

Select only the field the sidebar shows:

```diff
--- a/apps/realworld-dashboard/src/layout/sidebar-nav.tsx
+++ b/apps/realworld-dashboard/src/layout/sidebar-nav.tsx
 export function SidebarNav({ collapsed, onToggle }: { collapsed: boolean; onToggle: () => void }) {
-  const { recentlyViewed } = useWorkspaceStore()
+  const recentlyViewed = useWorkspaceStore((state) => state.recentlyViewed)
```

This is the reference fix from the dashboard's answer key. The run applied it and reverted it
afterwards with `git checkout`.

## Prove it with the same claims

The agent reloads the page, so no selection carries over, and runs the same `begin`, the same click
and `end`. Trimmed:

```text
pass vfy_afb004ba-1020-43ca-8a3f-5430235db164 "select one order"  10 commits, quiet after 880 ms (react, query, router)
  1 pass render SidebarNav max 0  {renders:0,mounts:0,updates:0,remounts:0,semantics:exact,instances:1,activeInstances:1}
  2 pass render BulkActionBar min 1  {renders:1,mounts:0,updates:1,remounts:0,semantics:exact,instances:1,activeInstances:1}
  3 pass boundaries clean  {caughtDuringWindow:0,caughtAtEnd:0}
! ui-outcome-not-observed: Genie does not check the screen; confirm it with the UI driver
attempt 2 for these claims on this tab; previous fail vfy_0f82808b-bf71-4fd4-a5b5-b9fd1e987a52; document reloaded since
```

The command exited 0. The sidebar rendered zero times, and the toolbar still rendered once. Genie
does not check pixels, so the agent asks the driver what the toolbar shows:

```text
$ agent-browser --session art-l6 snapshot -s '[aria-label="Bulk actions"]'
- toolbar "Bulk actions"
  - StaticText "1"
  - StaticText " selected"
  - button "Mark shipped" [ref=e216]
  - button "Put on hold" [ref=e217]
  - button "Cancel" [ref=e218]
  - button "Clear selection" [ref=e219]
```

A good report from Claude Code quotes both verdict lines, the failing ID and the passing ID, and the
driver's check of the screen.

## When this approach does not fit

- `verify` counts renders and checks effects and error boundaries. It does not measure time. For
  timing before and after a change, see [Optimize](/docs/guides/optimize).
- `react_render_causes` graded the store cause `inferred`, not `exact`. The changed field and the
  missing selector were enough here. When a cause is only inferred, read the code before you act
  on it.
- Genie needs a development build of React 18 or newer and the dev-server setup from
  [Install and connect](/docs/getting-started/install).

[Use it with your agent](/docs/getting-started/agent) covers the skill and running several agents
at once. [Verify a fix](/docs/guides/verify-a-fix) lists every claim form. For how this compares
with what a browser driver sees on its own, see
[What is an agentic React tool?](/docs/articles/what-is-an-agentic-react-tool)
