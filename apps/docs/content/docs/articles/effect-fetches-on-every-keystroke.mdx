---
title: Every keystroke fetched the activity feed. The dependency looked harmless
description: Typing 10 characters into a comment box sent 10 activity requests. Genie's effect audit named the inline array behind it, and verify proved the fix.
---

Typing "Looks good" into an issue's comment box sent 10 requests to `/api/issues/CORE-12/activity`, one per key. The cause was one prop, `types={['created', 'status', 'field']}`. The `useActivity` effect lists `types` as a dependency, so each keystroke re-rendered the page, built a new array, and fetched the feed again.

This walkthrough runs against `apps/realworld-legacy`, a React 18 app in this repo with webpack and Redux. Every command and output below comes from runs on 2026-11-19. The [raw evidence](https://github.com/Genie-sa/genie-react/blob/main/docs/article-evidence/effect-fetches-on-every-keystroke.md) has the full output.

## The effect audit names the dependency

The timeline shows what left the page, not which code sent it. `react_effect_audit` reads the effects of one component inside the same render window:

```bash
npx genie-react call react_effect_audit '{"component":"ActivityLog"}' --session upd-d
```

Trimmed to the one effect it found:

```text
effects:[{index:0,hookIndex:1,kind:effect,depsMode:list,depCount:2,scheduled:10,fired:10,updates:11,lastChangedDep:1,cleanupFunctionObserved:true,hasCleanup:true,
  note:"re-ran 10 times when no dependency changed value — dependency [1] is a new reference with equal contents; trace its producer and stabilize it or depend on its primitive fields",
  hotness:{label:hot,basis:reference-only-reruns,reruns:{valueChanged:0,referenceOnly:10,undetermined:0},…,scheduleReason:below-schedule-rate,…},
  hook:useEffect,customHooks:[useActivity],source:{file:/src/features/issue-detail/use-activity.ts,line:13,column:1,functionName:useActivity,sourceMapConfidence:mapped,role:hook-callsite},…}]
```

The effect ran 10 times. Dependency `[1]` changed reference every time and changed value zero times. `basis:reference-only-reruns` is why the label is `hot`. `scheduleReason` says `below-schedule-rate` because the effect was scheduled on 10 of 11 updates, and that rate decides the label only for an effect without a dependency array.

`source` points at the `useEffect` on line 13 of `use-activity.ts`, read through the module's source map (`sourceMapConfidence:mapped`). The column is 1 because this app's webpack config uses `eval-cheap-module-source-map`, which maps lines only. Genie 1.0.2 reported line 15, a line in the transformed module, and 1.1.0 fixed it. The audit's component source points at the JSX call site, `issue-detail-page.tsx:56`.

`react_effect_timeline` lists each run with the slot that changed:


## A new array on every render re-runs the effect

Here is the hook:

```ts title="src/features/issue-detail/use-activity.ts"
useEffect(() => {
  let cancelled = false
  request<ActivityEvent[]>(
    `/api/issues/${issueKey}/activity${toQueryString({ types: types.join(',') })}`,
  )
  // …
}, [issueKey, types])
```

And here is the parent:

```tsx title="src/features/issue-detail/issue-detail-page.tsx"
const [commentDraft, setCommentDraft] = useState('')
// …
<ActivityLog issueKey={issue.key} types={['created', 'status', 'field']} />
```

The comment draft lives in `IssueDetailPage`. Each keystroke calls `setCommentDraft`, `IssueDetailPage` renders again, and the JSX builds a fresh array literal. React compares dependencies with `Object.is`, so the new array counts as a change and the effect re-runs.

The hooks lint rule does not catch this. oxlint 1.87.0's port of [`react-hooks/exhaustive-deps`](https://oxc.rs/docs/guide/usage/linter/rules/react/exhaustive-deps.html) reported a missing dependency in a test file, then passed all three app files with exit 0. The dependency list is complete. The rule checks the hook, and the hook cannot know that its caller builds `types` fresh on every render.

## When this approach does not fit

- The effect tools see effects in React components. A request sent from an event handler, a class lifecycle method or a Redux thunk never shows up in `react_effect_audit`. Use the timeline request lane for those, and read the code that sends them.
- An effect with dependencies is `hot` only after it re-runs at least 3 times in the window (`hotnessCriteria.minUpdates:3`). If you type one character, read `fired` and `lastChangedDep` instead of the label.
- A constant only works when the array never changes. If the types come from props or state, wrap the array in `useMemo`, or pass `types.join(',')` and depend on the string. This walkthrough did not test those variants.
