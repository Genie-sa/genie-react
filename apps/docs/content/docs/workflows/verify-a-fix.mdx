---
title: Verify a fix
description: Declare what the fix must make true, drive the interaction, and get a pass, fail, refused or inconclusive verdict.
icon: ShieldCheck
---

`verify` turns "I think the fix worked" into a verdict with an exit code. You declare claims before the
interaction, drive the UI with your own driver, and end the window. Genie settles the app, keeps recording
for a short tail, freezes the evidence and checks every rule it would otherwise leave to you: coverage,
exact against inferred evidence, evicted events, remounts, overrides, reloads, Fast Refresh and hidden tabs.

## Run one verification

```bash
npx @genie-react/cli verify begin --session my-agent --name "type cert in filter" \
  --claim 'render StatusBadge max 0' \
  --claim 'render SearchScreen min 1' \
  --claim 'boundaries clean'
agent-browser --session my-agent type 'input[aria-label="Filter incidents"]' cert
npx @genie-react/cli verify end <id> --session my-agent
```

`begin` prints the verification ID, the resolved targets and the `verify end` command. `end` prints one line
per claim:

```text
fail vfy_… "type cert in filter"  4 commits, quiet after 640 ms (react, query)
  1 fail render StatusBadge max 0  {renders:4,mounts:0,updates:4,remounts:0,semantics:exact,instances:1,activeInstances:1}
  2 pass render SearchScreen min 1  {renders:4,mounts:0,updates:4,remounts:0,semantics:exact,instances:1,activeInstances:1}
  3 pass boundaries clean  {caughtDuringWindow:0,caughtAtEnd:0}
! ui-outcome-not-observed: Genie does not check the screen; confirm it with the UI driver
attempt 1 for these claims on this tab
```

Fix the code, then run `begin`, the same interaction and `end` again. The attempt line records earlier runs of
the same claims on the same tab and whether the code changed since, so a pass after failures on the same code
says so on its first line.

## Claims

| Claim | Holds when |
| --- | --- |
| `render <Name> max <N>` | matched instances rendered at most N times; a pass needs exact, complete evidence and an instance that was rendering |
| `render <Name> min <N>` | they rendered at least N times; a lower-bound count can pass |
| `render <Name> max <N> counting updates` | updates only, but a remount still fails unless you add `allow-remount` |
| `render <Name> only <cause>[,<cause>]` | every render had only exact causes from the list: `mount`, `children`, `router`, `props.<name>`, `state[<n>]`, `context.<Name>` or `query.<hash>` |
| `effect <Name>[#index] max <N>` | each effect executed at most N times; scheduling alone does not count |
| `effect <Name>[#index] settles` | the effect stopped executing after the app settled; the verdict prints the observation horizon |
| `boundaries clean` | no error boundary caught during the window and none is in an error state at the end |
| `boundaries clean-at-end` | no boundary is in an error state at the end |

A target is an exact component name, optionally narrowed with `@src/file.tsx` or `[key=value]`. Add a positive
control, such as `min 1` on a component the interaction must change: if the interaction never reaches the app,
the control fails instead of the run passing on an absence. `--claims <file>` accepts the same claims as JSON;
`npx @genie-react/cli verify begin --help` prints every option.

## Verdicts

| Verdict | Exit | Meaning |
| --- | --- | --- |
| `pass` | 0 | the evidence proves every claim |
| `fail` | 1 | the evidence proves at least one claim false; a failure decides the whole run |
| `refused` | 4 | the evidence is not good enough; each refusal names one reason and a `fix: $` command |
| `inconclusive` | 5 | complete evidence that does not decide, such as an excess that only StrictMode's replay explains |

A refusal is never a pass in disguise. `budget_exhausted` prints the `verify begin` command with the budget to
use; `no_activity` means no React commit happened, so the interaction probably went to another tab;
`not_quiescent` means work was still arriving. Run the fix, then the interaction again.

## While a window is open

Genie refuses `react_clear_renders`, `react_profile_start`, `react_profile_stop`, `devtools_interaction_begin` and
the override tools on that tab, because each would reset or skew the evidence. `verify abort <id>` releases the
window, and the hub expires one nobody ended after five minutes. `verify show <id> --claim 1` prints every
deciding item for a claim; `--section guards` shows each guard with its raw input.

Genie does not check what the user sees, uncaught errors outside error boundaries, or work that lands after the
tail. Confirm the visible result with the UI driver before you report the fix.
