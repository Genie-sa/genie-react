The Redux collector adds `redux_actions` and `redux_state`, and names the action behind each
`external-store` render cause that comes from the store. It supports Redux 4 and 5 and Redux
Toolkit 1.9 and 2.x, with any middleware and enhancers, and react-redux 8 and 9 for the render join.
It is development only: a production build resolves `genie-react/collectors/redux` to a stub that
never touches the store.

## Wrap the store before components render

`connect()` binds action creators to `store.dispatch` on its first render, and a component that
never re-renders keeps the `dispatch` it read then. Register the collector where the store is
created, so every component dispatches through Genie:

```ts title="src/store.ts"
import { configureStore } from '@reduxjs/toolkit'
import { reduxCollector } from 'genie-react/collectors/redux'

export const store = configureStore({ reducer })

export const genieRedux = reduxCollector(store, { name: 'app' })
```

Then hand it to the client:

- **Vite:** pass the store, `<Genie reduxStore={store} />`. Render `<Genie />` before the app's own
  components when you do not call `reduxCollector` yourself; it wraps the store while it renders.
- **Bundled client** ([other web bundlers](/docs/setup/other-web)): add `genieRedux` to the
  `collectors` list of `createGenieClient`.
- **Next.js:** call `registerGenieCollector(genieRedux)` from `genie-react/protocol` in the client
  component that already registers other collectors.
- **React Native:** pass `reduxStore: store` to `startGenie`, called before your components render.

Calling `reduxCollector` again for the same store returns the first collector. An app with several
stores registers each one; the tools then take a `storeId`.

## What it records

Each dispatch keeps its type, a depth-bounded copy of the action, its duration, whether it returned
or threw, whether the root state kept its identity, and which top-level slices changed. A dispatched
function is recorded as a thunk, and the actions it dispatches, now or later, name it as
`parentActionId`, which covers `createAsyncThunk` and RTK Query `initiate`. The history keeps the
last 500 records.

After each action, Genie compares the state objects that already existed against their contents
before the dispatch. An immutable reducer never changes an existing object, so any change is
reported as `mutation.status: "detected"` with the paths that changed, as when a reducer pushes into
`state.notes` and returns `state`. The comparison is bounded at about 1,000 property reads per action,
shared between slices, and stops at depth 6 and 64 entries per object; `scanTruncated` says when a
change past that bound would not be seen. Objects that are frozen, as Immer freezes Redux Toolkit
state, cannot change and are not compared. A change made in place between two dispatches is
reported at the next dispatch as `mutation-outside-dispatch`.

On a store with 3,240 entities, recording adds about 1–2.5 µs per dispatch, and the mutation check
about 30–40 µs more. Pass `{ detectMutations: false }` to keep only the recording.

## Action-to-render join

When a render's `external-store` cause comes from the collected store, the cause carries `redux`:
the store, how the hook was tied to it, and the actions that changed the state between this
component's previous render and this one, timed on React's own render clock. `evidence` is `exact`
only when Genie can prove that ordering. A `connect()` component nested under another `connect()` is
notified late, from its parent's layout effect, so its link is `inferred` unless React rendered it
in the previous commit. See `react_render_causes` and [`redux_actions`](/docs/tools/redux).

## Not supported

- Dispatches that bypass the wrapped `dispatch`: middleware that dispatches on its own, sagas,
  epics, and the RTK listener middleware. Genie still sees the state change and records it as
  `unrecorded-change` with no type.
- A store whose `dispatch` is read-only, or a store-like object without `getState` and `subscribe`.
- The render join for stores read outside react-redux or `useSyncExternalStore(store.subscribe, …)`.
- Store state made of class instances, Maps or Sets: only plain objects and arrays are compared.
- Redux DevTools' time travel and `replaceReducer` hot swaps are not recorded as actions.
