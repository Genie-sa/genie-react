Each browser tab is a session. Several apps, tabs, and agents can connect to one local hub.

## Name the tab

Add `_genie` to the app URL:

```text
http://localhost:3000/?_genie=checkout-agent
```

Pass the name to every `status`, `tools`, `call`, `batch`, and `capture` command:

```bash
npx @genie-react/cli status --session checkout-agent --wait 15000
npx @genie-react/cli call react_get_tree '{"depth":2}' --session checkout-agent
```

`status --wait` waits up to the given milliseconds for that session to be ready, so a script can run
it right after opening the page. On timeout it fails with `not_connected`. Without `--wait`, a
session that has not registered yet fails at once with `unknown_session`. In both failures,
`details.session.registeredTabs` is `0` when no browser tab has reached the hub, and the count of
other tabs otherwise.

`GENIE_SESSION` sets a default for one shell, but prefer the flag: each command stays
self-contained, and agent permission allowlists accept it without an `export`.

The name survives navigation, reloads, HMR, and reconnects. A physical session ID also works, but it
can change after a reconnect.

## Find the right session

```bash
npx @genie-react/cli status --sessions-only
```

Run the command from the app folder. Genie uses the local bridge discovery file. Several matching
bridges are an error. Pass `--session` (or set `GENIE_SESSION`) with a unique name, logical ID, or
physical ID before any mutation. A name shared by several tabs fails as ambiguous and lists the
matching tabs.

## How tabs are tracked

- **Logical session.** Each tab keeps one logical ID across reloads, navigations, and back/forward
  cache restores. Every page load in the tab is a new document with a higher generation. `status`
  shows one row per tab: its current document.
- **Default tab.** A call without `--session` goes to the only connected tab. Once a call has used a
  tab, later untargeted calls from the same agent stay on it, even after you open other tabs. Each
  agent has its own default, and untargeted calls never land on a tab another agent used in the last
  10 minutes. When several tabs are connected and none has been used yet, the call fails with reason
  `unknown_session` and hub code `SESSION_AMBIGUOUS`; when every tab is in use by another agent, it
  fails with `SESSION_CLAIMED`. In both, `details.session.connected` lists the tabs.
- **Reload grace.** When the default tab's document disconnects, the hub waits up to 5 seconds for
  it to come back. A tab that connects during that wait, such as a React Native app after a Metro
  reload, becomes the default at once. If exactly one other tab is open, it answers in the
  meantime. With several other tabs open, calls fail with `SESSION_RELOADING` and `retryInMs`
  until the tab returns or the wait ends. Whenever another tab answers for the default, the CLI names it in a stderr
  `session-retargeted` diagnostic.
- **Supersession.** A new page load in a tab replaces the previous document. Calls still pending
  on the old document fail at once with `SESSION_SUPERSEDED`. If the tool is not read-only,
  `details.mayHaveCompleted` is `true` and the message says the call may have completed, so check
  app state before you retry. If the old document was active within the last heartbeat, the hub first gives it a moment to prove it is still running. A duplicated tab
  (`window.open`, tab duplication) proves this and keeps the identity, and the copy gets a new
  logical ID. A prerendered page joins only when it is shown.

Use a direct bridge only when discovery is not enough:

```bash
export GENIE_BRIDGE_URL=ws://127.0.0.1:4390/__genie/ws
```

## Working in parallel

Several agents can share one machine, one dev server, and one hub. Genie keeps each agent's evidence
its own, or says why it cannot.

### What an agent must do

- Open its own tab with its own name (`?_genie=<name>`) and pass `--session <name>` on every command.
- Run the CLI from its own checkout or worktree, so discovery finds that worktree's hub.
- Set `GENIE_AGENT=<name>` when it shares a shell or a worktree with another agent and no harness
  session tells them apart, for example subagents that run their own captures.

### What Genie guarantees

- **Identity.** Each CLI process names its caller: `GENIE_AGENT` when set, else a hash of the Claude
  Code (`CLAUDE_CODE_SESSION_ID`) or Codex (`CODEX_THREAD_ID`) session, else a hash of the git
  worktree root. Without any of them, calls share one anonymous caller, as before.
- **Routing.** A call reaches only the tab it targets. Untargeted calls keep a default per agent and
  skip tabs other agents use. A shared name opened in two tabs fails as ambiguous.
- **Per-tab state.** A tab has one render window, one profile, one timeline, one set of overrides
  and its Query simulations. A read from a window another agent restarted, paused, or changed with a
  state-changing tool, or from a window that a reload replaced, fails instead of returning the other
  window's data. Resetting overrides, restoring or re-simulating a Query, or starting a timeline
  while another agent holds one is refused. A hold lapses after 5 minutes without a call from its
  agent.
- **Several hubs.** Discovery never leaves the current git checkout or worktree. A worktree nested in
  another checkout reaches only its own hub, and a monorepo root with several live hubs below it
  lists them instead of picking one. Two dev servers started for one project at once publish one
  consistent endpoint and token; the other server says so in its log.
- **Shared files.** Oversized outputs, feedback drafts, and agent tokens use unique names and atomic
  writes, and a spilled output is kept for at least an hour.

### What each error means

| Failure | Meaning | What to do |
| --- | --- | --- |
| `unknown_session`, `SESSION_CLAIMED` | Every connected tab is in use by another agent | Open your own tab and pass `--session`; pass `--session` to share one deliberately |
| `conflict`, `OBSERVATION_SUPERSEDED` | Another agent restarted, paused, or changed your render window or recording, or the tab reloaded (`details.ownership.cause`) | Start a new window and repeat the interaction on your own tab |
| `conflict`, `STATE_HELD` | Another agent holds the overrides, Query simulation, or recording you would reset | Leave it; use your own tab or retry after that agent finishes |
| `! session-shared` diagnostic | Another agent used this tab recently | Move to your own tab |
| `! window-displaced` diagnostic | Your call disturbed another agent's window | Move to your own tab |

## How this helps the agent

The agent can keep one stable target through a long edit and reload loop. It will not clear renders,
change Query state, or navigate another agent's tab by mistake.
